1 Arquitectura de la Aplicación e Integración con LLM

La plataforma Merkostore es una solución moderna de comercio electrónico estructurada como una API REST basada en Spring Boot 3.2.4 (Java 17) con persistencia en MongoDB y una interfaz de usuario cliente desacoplada y responsiva. Para cumplir con los requerimientos de la asignatura, se incorporó un Agente Inteligente / Chatbot ("MerkoBot IA") capaz de atender las consultas de los clientes sobre el catálogo, horarios, envíos, métodos de pago y recomendaciones personalizadas en lenguaje natural.

Spring Boot 3.2.4 Java 17 LTS Spring Data MongoDB Groq Cloud API (Meta LLaMA 3.1 8B) Spring Security 6 JWT (jjwt 0.11.5) HTML5 / CSS3 / ES6

1.1 Flujo de Inferencia y Estrategia RAG (Retrieval-Augmented Generation)

Para garantizar respuestas precisas y actualizadas sin alucinaciones, la integración implementa un patrón RAG Liviano (Retrieval-Augmented Generation) en tiempo de ejecución:

  1. Recepción de la Petición: El cliente web envía la consulta mediante POST /api/v1/public/chat con el texto del usuario, el ID de la tienda (storeId) y el identificador de sesión (conversationId).
  2. Persistencia del Mensaje del Usuario: El servicio registra de inmediato el mensaje en MongoDB (colección chat_messages) para auditoría e historial.
  3. Recuperación de Contexto (Retrieval): ChatbotService consulta en tiempo real:
    • La configuración de la tienda activa (StoreConfigRepository): nombre comercial, teléfono de WhatsApp, horario de atención, costos de envío y métodos de pago.
    • Los productos disponibles (ProductRepository.findByStoreIdAndIsAvailableTrue()): nombres, descripciones, categorías, precios y stock.
  4. Inyección en el Prompt del Sistema (Augmentation): Se construye un prompt de sistema restrictivo y estructurado que delimita el rol de MerkoBot exclusivamente a los productos y políticas de la tienda.
  5. Llamada al LLM (Generation): Se invoca a la API de alta velocidad de Groq consumiendo el modelo llama-3.1-8b-instant mediante RestTemplate con formato OpenAI-compatible.
  6. Mecanismo de Resiliencia (Fallback Autónomo): En caso de indisponibilidad de la API externa o ausencia de API Key, un Motor Experto de Dominio local analiza las intenciones semánticas y provee respuestas inmediatas con tarjetas interactivas de productos reales.
  7. Persistencia y Respuesta: Se persiste la respuesta generada y se retorna al cliente estructurada con sugerencias dinámicas y productos relacionados.

2 Prototipo de Clases del Chatbot / Agente Inteligente

2.1 Adaptación del Proyecto de Referencia (Educhat-notes a Merkostore)

El proyecto de referencia Educhat-notes propone un patrón de orquestación donde un controlador REST recibe la consulta, un servicio construye el contexto semántico y se conecta a un LLM para responder preguntas sobre apuntes académicos.

Para la plataforma Merkostore, se adaptó dicha filosofía al dominio del comercio electrónico minorista:

Componente Enfoque Educhat-notes (Referencia) Adaptación en Merkostore (Implementado)
Dominio y Contexto Notas de estudio, materias, apuntes académicos en PDF/texto. Catálogo de productos en stock, promociones, precios, horarios, métodos de pago y políticas de envío de la tienda.
Persistencia de Mensajes Historial volátil o plano en memoria. Colección chat_messages en MongoDB con indexación por conversationId y storeId para trazabilidad.
Estructura de Respuesta Texto plano con la síntesis académica. Respuesta enriquecida: texto explicativo + lista de sugerencias rápidas + tarjetas de productos identificados (con ID, precio e imagen).
Acciones en Front-End Lectura pasiva de respuestas. Acción interactiva directa: botón "Agregar al carrito" en los productos recomendados por MerkoBot.
Tolerancia a Fallos Error 500 si la API externa del LLM no responde. Fallback transparente: Si Groq LLM falla o no hay API key, se activa el motor de reglas de dominio local sin interrumpir al usuario.

3 Actualización de las Vistas del Front-End

3.1 Componentes de la Interfaz de Usuario (UI) de MerkoBot

Para evidenciar de manera tangible la integración con el usuario final, se enriqueció la vista principal de Merkostore (en index.html, estilizado en styles.css y controlado con app.js):

  • Botón Flotante (FAB con pulso luminoso): Ubicado permanentemente en la esquina inferior derecha con badge distintivo de IA y micro-animación pulsante para invitar a la interacción sin obstruir el contenido.
  • Panel Deslizante (Chat Drawer): Al hacer clic en el FAB, se despliega una interfaz fluida con encabezado personalizado de la tienda ("MerkoBot IA - En línea"), botón para reiniciar conversación y botón de cierre.
  • Chips de Sugerencia Rápida: Botones interactivos que permiten consultar preguntas frecuentes con un solo toque (ej.: "¿Qué productos tienen?", "¿Cuáles son los medios de pago?", "Ver ofertas del día").
  • Indicador Visual de Escritura (Typing Dots): Animación de tres puntos pulsantes mientras el backend o el LLM procesa la respuesta.
  • Tarjetas de Productos Recomendados: Si el usuario pregunta por un producto específico (ej.: "manzanas" o "arroz"), el chatbot no solo responde textualmente, sino que renderiza una mini-tarjeta interactiva con foto, precio y botón "Agregar al Carrito", permitiendo comprar directamente desde la conversación.

4 Evidencia de Control de Acceso y Seguridad

4.1 Mecanismo Stateless con Spring Security 6 y JWT

La seguridad de Merkostore se diseñó bajo el principio de arquitectura sin estado (Stateless), cumpliendo con los estándares modernos de desarrollo de APIs REST escalables:

  • Deshabilitación de CSRF: Dado que las peticiones se autentican mediante tokens en cabeceras HTTP (Authorization: Bearer <token>) y no mediante cookies de sesión, se deshabilita la protección CSRF según las directrices de Spring Security para APIs REST.
  • Filtro Personalizado JWT (JwtAuthenticationFilter): Intercepta cada petición entrante, extrae el token del header Authorization, valida la firma criptográfica (HMAC-SHA256 con llave secreta de 256 bits) y la fecha de expiración mediante JwtTokenProvider.
  • Control de Acceso Basado en Roles (RBAC): Los usuarios autenticados con el rol ROLE_ADMIN tienen acceso exclusivo al panel administrativo (gestión de productos, reportes financieros y configuración de tienda).
  • Exposición Pública Controlada del Chatbot: El endpoint /api/v1/public/chat se expone públicamente (permitAll()) para que cualquier visitante de la tienda pueda interactuar libremente con el asistente inteligente sin requerir registro previo.

Instrucciones de Despliegue y Ejecución Local

  1. Clonar el repositorio:
    git clone https://github.com/cristbarr066-cloud/merkostore.git cd merkostore
  2. Configuración de Variables de Entorno (Opcional para Groq LLM):

    En el archivo src/main/resources/application.properties o mediante variable de entorno del sistema:

    merkostore.llm.groq.api-key=${GROQ_API_KEY:your_groq_api_key_here} merkostore.llm.groq.model=llama-3.1-8b-instant spring.data.mongodb.uri=mongodb://localhost:27017/merkostore
  3. Compilar y Ejecutar con Maven:
    mvn clean spring-boot:run
  4. Acceso a la Aplicación:

    Abrir en cualquier navegador moderno: http://localhost:8080/ para interactuar con la tienda y con MerkoBot IA.

7 Conclusiones

La integración del Agente Inteligente / Chatbot en la plataforma Merkostore demostró la efectividad de los patrones arquitectónicos modernos aplicados al comercio electrónico:

  1. Estrategia RAG Liviana y Precisa: Al inyectar el catálogo de productos y los metadatos de la tienda directamente en el prompt del sistema hacia llama-3.1-8b-instant en Groq, se logró eliminar el riesgo de alucinaciones en precios o productos inexistentes, proporcionando información 100% verídica en milisegundos.
  2. Alta Resiliencia Operativa: La arquitectura de dos niveles (LLM externo con respaldo de motor experto local) garantiza que la tienda nunca deje de asistir a los usuarios, manteniendo operativas las recomendaciones incluso en ausencia de conexión a Internet externa o indisponibilidad de API Keys.
  3. Experiencia de Usuario Fluida y Accionable: La inclusión del botón FAB con pulso luminoso, la ventana conversacional moderna y, fundamentalmente, la posibilidad de añadir productos recomendados al carrito de compras con un solo clic dentro del chat, transforma el agente de un simple canal informativo en un asistente de ventas activo.
  4. Seguridad Robusta y Desacoplada: La implementación de Spring Security 6 con JWT aseguró la total protección de los paneles administrativos (ROLE_ADMIN) mientras brindó libre acceso al catálogo y al asistente para todos los clientes (permitAll) sin sobrecargar la memoria del servidor gracias al modelo stateless.
Certificación de Validación:
Todas las clases desarrolladas fueron verificadas y compiladas satisfactoriamente mediante mvn test-compile y los componentes Front-End se encuentran activos e integrados en el código fuente del proyecto.
